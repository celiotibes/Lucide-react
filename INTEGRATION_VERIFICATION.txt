VALIDATION RULES IMPLEMENTED
================================================================================

EMAIL FIELDS:
  Pattern: ^[^\s@]+@[^\s@]+\.[^\s@]+$
  Checks: Format + SQL injection
  Applied to: /auth/login, /auth/register
  Example: ✓ user@example.com | ❌ test@ex'; DROP

NUMERIC FIELDS:
  Checks: Number format, NaN, Infinity
  Detected by: Field names containing (valor, value, amount, price)
  Example: ✓ 123.45 | ❌ NaN | ❌ Infinity

STRING FIELDS:
  Checks: SQL keywords, script tags, event handlers, safe content
  Example: ✓ "normal text" | ❌ "SELECT *" | ❌ "<script>"

ARRAY FIELDS:
  Validation: Each element validated recursively
  Depth limit: 10 levels maximum
  Prevents: Stack overflow, infinite recursion

================================================================================
ERROR CODES & HTTP STATUS
================================================================================

VALIDATION_ERROR (400)
  - Generic validation failure
  - Request rejected before sending

MALICIOUS_CONTENT_DETECTED (400)
  - SQL keywords, scripts, or event handlers found
  - Request blocked immediately

INVALID_EMAIL (400)
  - Email format invalid or contains suspicious content
  - Request rejected

INVALID_NUMBER (400)
  - Numeric field validation failed
  - Field value NaN, Infinity, or invalid format

SANITIZATION_ERROR (400)
  - Critical sanitization failure
  - Request rejected

UNKNOWN_ERROR (500)
  - Unexpected error type
  - Used for compatibility
